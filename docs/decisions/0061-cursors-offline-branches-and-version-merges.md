# ADR 0061：光标协作、离线分支与版本合并

日期：2026-11-05（Asia/Shanghai）。状态：实施中，后端第一阶段已验证，前端与整体验收待完成。

## 来源与替代

用户确认正文实时保存、共享光标与选区、点击成员定位；掉线冻结个人最后确认的基线，允许继续在本地分支编辑，在线成员继续工作。历史版本视为可删除草稿，当前最新版不能删除。正式合并期间整篇最新版只读，在线尚未确认的输入仍须保留并恢复。

此决定替代 ADR0044 的“正文只在显式保存时提交”阶段选择；源码原样保留、源码/可视化均可编辑、稳定区块编号、PostgreSQL 提交后 ACK 等约束保持。前台发布与工作草稿分开。

## 数据与边界

- collab-2 每块以源文 Y.Text 为唯一正文；源码和可视化是投影。原 collab-1 仅保留既有调用窗口，新编辑器请求 source_first；旧文档切换时保留完整基线并换 epoch，不能静默把旧队列写入新文档。
- PostgreSQL 保存实时正文、增量及操作回执；显式检查点与合并记录保存完整快照。空闲检查点按实际输入时间和最小间隔合并生成。Redis 只承担临时成员/选区和唤醒；浏览器草稿使用 IndexedDB，账号/站点/文章/页面会话隔离。
- 离线分支保存基线 epoch/截点、原始内容与未确认操作。恢复时先核对服务端回执，对已接收但丢失 ACK 的本人操作选择性补入共同基线，再进行三方比较。
- 分支快照、历史草稿、合并结果与已发布投影独立。历史允许软删除；仍被分支依赖的内部基线和引用保留。本阶段没有物理压缩/GC 或媒体精确引用回收。

## 在线输入与合并竞争

所有写入沿相同引用锁、草稿行锁和合并租约检查串行。若输入先提交则纳入合并目标；若合并先取得锁，迟到写入返回40980，客户端保存为恢复分支。禁止只禁用前端按钮。

合并会话固定目标 epoch/序号/修订，结果在独立草稿中处理。60秒租约由发起人续期，取消或超时解锁，结果记录仍保留。完成时同事务校验目标、写检查点/来源、切换文档 epoch、推进最新版并解锁；旧连接必须恢复基线，不能自动重放旧 outbox。其他文章和前台已发布内容保持独立。

三方合并先按稳定块 ID 判断新增/删除/修改，再处理顺序、文本和属性。源码不重排格式；重叠修改与结构歧义明确列为冲突。人工决策和结果保存到合并会话；完成前校验全部冲突、正文、媒体与权限。

## 第一阶段验证

显式0017迁移与collaboration 2.0.0契约已实现。13项正文/合并针对性测试通过；真实双API/PostgreSQL/Redis用例通过（15.89秒），覆盖在线输入与开始合并竞争、迟到更新、丢失ACK去重、各写入口锁、取消、完成幂等、事务失败回滚、历史删除、旧epoch拒绝及租约超时。完整前端/浏览器/生产构建和实际容器迁移尚未完成，不把后端阶段结果作为整体交付。
